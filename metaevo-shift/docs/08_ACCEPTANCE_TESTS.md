# 08｜実装受け入れテスト（絶対条件）

## A. 初回60分・本人の主体性
- [ ] 8分の価値/利用説明から初回入力へ移り、同一アプリ内で回答を保存できる。
- [ ] 質問Q01–Q18とルートA–Dが仕様どおり存在する。Q10『該当なし』でも先へ進める。
- [ ] 目的未設定のAルートが、探索テーマ→具体的な体験行動→証拠へ進める。
- [ ] Bルートで願望が非公開のまま保存され、公開を求めない。
- [ ] Cルートで『できる見込みがない/やり方不明』を学習実験へ変換できる。
- [ ] Dルートで実行条件・妨げへの代替策を設定できる。
- [ ] 途中終了、ブラウザー再起動、オフラインから回答を再開できる。
- [ ] 感情・年収・人生理念を必須にせず、スキップと修正が可能。
- [ ] ワーク中の入力がそのまま翌日の『今日』に現れ、再入力不要。

## B. 日次と休日
- [ ] 朝、当日の『前進/整える/回復』を選べる。回復日を未達成扱いしない。
- [ ] 目標未設定でも『今日の探索行動』を開始できる。
- [ ] 重要行動は原則1件。開始まで2–3タップ以内。
- [ ] 内的な切替と外部の突発中断を別イベントで保存する。
- [ ] 重大な緊急対応ではアプリ入力より安全・対応を優先する。
- [ ] 外部中断前の次の一手と復帰時刻を保存でき、予定と実績が分かれる。
- [ ] 行動していない日・休息日・未記録日・未計画日を混同しない。
- [ ] 日次記録がない日も次の日に簡単に再開できる。連続日数の罰なし。
- [ ] 日中の急な切替を後から追記でき、編集後にレポートが再計算される。

## C. 成長・成果の区別
- [ ] 4層：行動、能力/学習、現実の成果、価値との一致を別々に表示する。
- [ ] 実行のみから『成果が出た』『自己実現できた』と自動断定しない。
- [ ] 目標ごとに成果証拠の種類・単位・基準値・計測日を保持する。
- [ ] 記録のある8日中6日着手なら75%と表示し、残る予定2日は不明と表示。
- [ ] 分母0は0%ではなく『未計測』。収入・能力等の推論を自動生成しない。
- [ ] 目標を変更しても過去の行動記録は保持。本人の削除権は維持。

## D. 7/14/30/60/90日レビュー
- [ ] Day0は初回日、Day1は翌日、Day14は14日後。日本時間で正しく計算。
- [ ] Day7には3つの軽い質問。省略した人にペナルティなし。
- [ ] Day14は事実→変化→原因仮説→次期実験まで一通り完成できる。
- [ ] 原因は仮説として本人が支持/反証/判断不足/否定を選べる。
- [ ] Day30/60/90では目標・実行条件・本人の自律的判断・成果が確認できる。

## E. データと技術
- [ ] iPhone Safari/ホーム画面PWA、Android Chrome、PCの基本動作を確認。
- [ ] オフライン時にワーク入力、重要行動、レポート表示、バックアップが機能する。
- [ ] 初回ワーク前にiOSの保存領域分離について案内。Safari→PWAは手動エクスポート/復元ができる。
- [ ] バックアップは`schemaVersion`付きJSON。インポートはバージョン・データ内容・サイズを検証し、安全に復旧する。
- [ ] 外部AI API呼び出しなし、個人本文のサーバー自動送信なし。
- [ ] 初期状態でデータ共有なし。メンター/講師が個人データを勝手に閲覧できない。
- [ ] 端末データの削除は2段階確認、データ移行時の破損から安全に復旧。
- [ ] 同時多重タップでもイベント重複なし。データのマイグレーション・タイムゾーンをテスト。
- [ ] 320px画面、タップ領域、読み上げ、キーボード操作、モーション軽減に対応。

## F. 利用者への危険な説明を防ぐ
- [ ] 『14日で習慣完成』『必ず稼げる』『潜在意識を診断』『あなたは逃避タイプ』等の文言なし。
- [ ] 本人の望みが本当に分からない場合と、評価の不安で言いにくい場合を分ける。
- [ ] 原因仮説の単一の回答だけで人格評価を下さない。
- [ ] 自己分析より先に安全・休息・実際の行動を優先できる。

## G. E2E必須シナリオ
1. A：方向性が分からない人 → 非公開探索 → 体験行動を予定 → 実行 → Day14で学びを確認。
2. B：年収目標は胸の内にあるが人に言えない人 → 公開なし → 仮の目標 → 最小行動 → Day14で変化確認。
3. C：計画方法が分からず見込みが低い人 → 学習実験 → 最初の方法を試す → Day14で実行可能性を再評価。
4. D：計画しても資料整理をしてしまう人 → 内的切替 → 理由記録（任意） → 2分着手 → 実成果を確認。
5. E：顧客トラブルが来た人 → 即対応 → 復帰地点記録 → 復帰・未復帰の事実を記録。
6. F：休日に休息した人 → 回復日として保存 → 仕事の着手率の分母から除外。
7. G：14日中の未記録が多い人 → 0%断定なし → データ不足として次の支援を提案。
8. H：行動は増えたが成果がない人 → 戦略・能力・市場の反応を再検証する提案。
9. I：本人が目標を変えたい → 価値観に沿って選び直す → 旧実験は履歴保存。
10. J：ワーク中に回線を切る → データ消失なく再開、オン/オフ両方で集計同一。

**設計完了とアプリ開発完了は異なる。この一覧は実装後の合否判定用。**
