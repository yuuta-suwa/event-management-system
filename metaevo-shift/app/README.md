# MetaEVO Shift（メタエボシフト）―自分革命システム― アプリ本体 v2.3

設計資料（`../README.md` ほか `../docs` `../workshop` `../spec`）を唯一の仕様基準として実装した、スマートフォン向けのローカルファーストPWAです。

- ログインなし・サーバー保存なし・AI API料金なし。データは端末のIndexedDBだけに保存
- オフラインで動作（Service Workerで全画面をキャッシュ）
- JSONバックアップ／復元（v2.0 → v2.1 の非破壊マイグレーション対応）
- 技術：React 19 + TypeScript + Vite 8 + Dexie（IndexedDB）+ Zod + vite-plugin-pwa + Vitest + Playwright

## iMacでの起動方法

必要なもの：Node.js 20.19 以上（推奨 22）。[nodejs.org](https://nodejs.org/) のLTS版をインストールしてください。

```bash
cd metaevo-shift/app
```

```bash
npm install
```

開発用サーバー（画面の確認用）：

```bash
npm run dev
```

→ ブラウザーで **http://localhost:5173** を開きます。

本番と同じ状態（オフライン・インストール可能）で確認する場合：

```bash
npm run build
```

```bash
npm run preview
```

→ **http://localhost:4173** を開きます。

### 確認する画面

1. 初回起動：「MetaEVO Shift｜自分革命システム」、インストール案内、プライバシー説明 →「初回ワークを始める」
2. 初回ワーク：8枚の説明（00:00〜08:00）→ Q01〜Q18（区間と目安時間つき）→ Q07のあとにA〜Dルートの追加質問 → まとめ →「保存して『今日』へ」
3. 今日：前進／整える／回復、最重要行動、「今から始める」、別のことをしたい／予定外の対応／何から始めるか分からない／計画を変更、夜の1分確認
4. 人生の軸：生き方・理念・目標・改訂履歴、ルート変更、「人生の時間｜LIFE CLOCK」（初期はオフ）
5. 成長：行動／能力・学習／現実の成果／価値との一致の4層
6. 振り返り：直近14日の記録、後から追記、Day7・Day14・Day30/60/90
7. 右上の人型アイコン → 設定：バックアップ保存・復元、デモ表示、全削除

講師の投影や動作確認には「設定 → デモ表示に切り替える」を使ってください（後述）。

## iPhone実機で別途確認すべき項目

自動テストはPC上のChromiumで実行しています。次はiPhone実機で確認してください。

1. **HTTPSで配信すること**：Service Worker（オフライン）とホーム画面アプリとしての動作には、`localhost` 以外ではHTTPSが必要です。iMacの `http://192.168.x.x:4173` をiPhoneで開くと画面は動きますが、オフライン動作は確認できません。確認方法は次のどちらかです。
   - 静的ホスティング（HTTPS）に `dist/` を置く（**公開デプロイのため、実施前にご判断ください**）
   - iMacで `mkcert` によるローカル証明書を作成し、ルート証明書をiPhoneに信頼させて `https://` で配信する
2. Safariで開く → 初回画面に「ホーム画面に追加してから」の案内が出る
3. ホーム画面に追加 → アイコン・名称「MetaEVO Shift」、起動時に「アプリ版で開いています」の表示
4. Safari側で入力したデータがホーム画面版に**引き継がれない**ことの確認と、バックアップ → 復元での移行
5. 機内モードでホーム画面版を起動し、ワーク入力・開始・夜の確認・バックアップができる
6. バックアップの保存先（「ファイル」アプリ・共有シート）と、ファイルを選んでの復元
7. VoiceOverで主要ボタン・選択肢・LIFE CLOCKの要約が読み上げられる
8. 文字サイズを大きくした状態、ノッチ・ホームバー周り（safe-area）の表示
9. 数日使ったあと、iOSのストレージ整理でデータが残っているか（長期間未使用のサイトデータは削除される場合があります）

Android Chrome とPCブラウザーでも、インストール・オフライン・バックアップを一通り確認することを推奨します。

## バックアップと復元のテスト手順（手動）

1. 初回ワークを完了し、「今日」で「今から始める」を押す
2. 設定 →「バックアップを保存」→ `metaevo-shift-backup-YYYYMMDD.json` が保存される
3. 設定 →「すべての記録を削除する」→「削除」と入力 →「完全に削除する」
4. 初回画面に戻ったら「バックアップから復元する」→ 設定 →「ファイルを選ぶ」で手順2のファイル
5. 内容のプレビュー（初回ワーク・件数）を確認 →「置き換えて復元する」
6. 「今日」に同じ行動が「実行中」で表示されることを確認
7. 異常系：拡張子だけ.jsonの別ファイルや、内容を書き換えたファイルを選ぶと、エラー表示のみで端末データは変わらない

## テスト用データと本人データの分離

- 本人のデータ：IndexedDB `metaevo-shift`
- デモ・テスト用データ：IndexedDB `metaevo-shift-demo`（架空の内容。設定 →「デモ表示に切り替える」）
- デモ表示中は全画面に「デモデータ表示中」の帯が出ます。デモの投入処理は本人用DBへの書き込みを拒否します（unit testで確認）
- デモのバックアップのファイル名には `DEMO` が付き、最終バックアップ日時も更新しません
- 自動テストは毎回空のブラウザー環境で実行し、本物のデータには触れません

## 仕様からの補足・解釈（設計書との差分の記録）

| 箇所 | 対応 | 理由 |
|---|---|---|
| 保存先 `app/` | リポジトリの `metaevo-shift/app/` に配置 | このリポジトリのルートは既存のNext.jsアプリで、ルート直下の `app/` はその動作を壊すため。設計資料は `metaevo-shift/` に同梱し、ルートの tsconfig / eslint / vitest から除外 |
| Day7の3問 | 「難度は合っている（実行可能だったか）」「負担・先週の障壁」「本当の進捗を何で確かめるか（証拠）」 | 04章と06章で文言が異なるため統合 |
| 成果指標の保存先 | `goal.outcomeMeasure`（種類・単位・基準値・計測日・目標値）を追加プロパティとして保持し、`outcomeMeasureId` で参照 | スキーマに測定定義の置き場がない。追加プロパティはスキーマ上許容 |
| SAMPLE_FIXTURE の `evidence e1`（「予定」を証拠として保存） | 計画からは証拠を作らない | H章「証拠を勝手に生成しない」を優先 |
| 補助プロパティ | `workshop.currentStepId`、`dayPlan.doneWhen`、`experiment.doneWhen / evidencePlan / goalId / changedCondition`、`evidence.localDate`、`review.answers / hypotheses` | 途中再開・終了判定・ローカル日付の集計に必要。公式JSON Schemaで検証済み（追加プロパティ許容） |
| ワーク回答の保存形式 | `workshop.answers[ID]` は `{ choice, choices, text, ... }` のオブジェクト。v2.0サンプルの文字列形式も読み込み可能 | スキーマ上は任意型 |
| Day0の初回行動 | Q15で「今日」を選んだ場合、Day0の行動も最初の14日間の集計に含める | Day1開始のみだと初回の着手が振り返りから漏れるため |
| ルールの優先順位 | R_NO_DIRECTION〜R_NO_PLAN（5〜8）は「今日の行動が未設定」のときに評価 | 行動が設定済みの日に探索の促しを繰り返し出さないため。本人が押したボタンの文脈は常に優先 |
| 安全の案内 | 119／110、こころの健康相談統一ダイヤル（0570-064-556） | 医療判断はせず窓口のみ案内。番号は公開前に最新情報の確認を推奨 |

## 残る制約

- iPhoneの実機確認は未実施（上記チェックリスト参照）。オフライン・インストールの確認にはHTTPS配信が必要
- データは端末内のみ。端末の故障やブラウザーのデータ削除で失われるため、利用者による定期バックアップが前提
- iOSはSafariとホーム画面版で保存領域が分かれる場合があり、移行は手動（バックアップ→復元）
- ルールエンジンは決まった規則に基づく集計と定型の提案のみ。自然文の分析はしない
- 14日間プログラムとLIFE CLOCKの効果は未検証（設計資料 09章のとおり）
- ビルド時にだけ使う workbox-build 関連の依存に、npm audit で中程度の脆弱性が報告されています（配布物には含まれません）
