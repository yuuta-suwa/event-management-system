# 運用ランブック

## 毎日の確認

- 通知履歴の失敗・再試行件数、当日・翌日のイベント、未入金、残席を確認する。
- DBバックアップ成功、空き容量、アプリのエラー率を確認する。

## イベント当日

1. 受付端末を充電し、カメラ権限とネットワークを確認する。
2. 対象イベントを選び、練習用チケットで受付OK・受付済み・未入金・別イベントを確認する。
3. 通信障害時は紙名簿へ時刻と担当者を記録し、復旧後に受付処理する。
4. 未入金者は現地支払、受付拒否、管理者確認のいずれかを記録する。

## 通知障害

- LINEアクセストークン、参加者の連携状態、通知履歴のエラーを確認する。
- 429は送信頻度を下げ、401はトークンを再発行する。
- ジョブは最大3回まで15分間隔で再試行する。最終失敗はメールまたは電話へ切り替える。

## アカウント事故

- 退職・紛失時は対象ユーザーの `status` を即時 `SUSPENDED` にする。既存セッションも次回アクセスで拒否される。
- 秘密情報漏えい時は該当Secretをローテーションする。`AUTH_SECRET` の変更は全セッションを失効させる。
- 監査ログでactor、action、entity、before/after、時刻を確認する。

## データ保護と障害連絡

- CSVは必要な端末だけに保存し、利用後は安全に削除する。
- 障害連絡には発生時刻、影響イベント、影響機能、対象人数、暫定対応、次回更新時刻を記載する。
