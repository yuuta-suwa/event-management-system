# メール配信の設定（QRチケット）

> 方針: 送信サービスは `src/features/email/provider.ts` だけに依存している。サービスを替える場合はこのファイルを差し替える。
> **有料契約や独自ドメインの設定は管理者が判断して行う。** 未設定の間、システムはメールを送らず、`/emails` に「送信しない」と記録する（他の機能には影響しない）。

## 送信サービスの比較（2026-11 時点の一般的な条件。契約前に各社の最新の料金ページを確認すること）

| サービス | 無料枠の目安 | 連携の容易さ | 独自ドメイン | 備考 |
|---|---|---|---|---|
| **Resend（採用）** | 月3,000通・日100通程度 | REST API 1本。本システムは実装済み | 必須（自分のドメインのDNSにSPF/DKIMを登録） | 送信履歴・到達状況を管理画面で確認できる。小規模イベントなら無料枠で足りる |
| Amazon SES | 低価格の従量課金（1,000通あたり数十円） | AWS設定が必要。初期は送信制限（サンドボックス）の解除申請が必要 | 必須 | 大量送信向き。設定の手間が大きい |
| SendGrid | 無料プランは縮小・試用中心 | API容易 | 必須 | 継続費用が発生しやすい |
| Postmark | 月100通程度の無料枠 | API容易 | 必須 | 到達率は高いが無料枠が小さい |

判断基準: 無料枠、実装の容易さ（実装済みのResend）、到達率（独自ドメインの認証が前提）、送信履歴、継続費用。

## 設定手順（Resend）

1. resend.com でアカウントを作成する（管理者本人の名義で）。
2. 「Domains」で送信に使うドメイン（例: 自社ドメイン）を追加し、表示された DNS レコード（SPF・DKIM）をドメインの DNS に登録して「Verified」にする。
   - ドメインが未認証だと、自分以外の宛先には送れない。
3. 「API Keys」で送信用キーを作成する（権限は Sending access）。
4. Vercel の Environment Variables（Production）に登録して再デプロイする。
   - `RESEND_API_KEY`: 手順3のキー
   - `EMAIL_FROM`: 例 `イベント事務局 <tickets@あなたのドメイン>`（認証済みドメインのアドレス）
   - 任意: `EMAIL_REPLY_TO`（返信先）、`CONTACT_EMAIL`（本文の「お問い合わせ」）
5. `/emails` を開き、赤い「未設定」の表示が消えていることを確認する。
6. **テスト送信**: 自分が保有者のテストチケットのチケット番号を「チケットメールを再送」に入れて送信し、受信・本文・QR画像を確認する（本番の参加者へのテスト送信は行わない）。

## 送信されるメール

| いつ | 種別 | QR・受付コード |
|---|---|---|
| 申込を受け付けたとき | 申込受付 | なし |
| 入金確認でチケットが有効になったとき | 入金確認・QRチケット | あり（リンク＋PNG添付＋6桁の受付コード） |
| チケットを譲渡・配布で受け取ったとき | 譲渡受取 | 入金済みならあり |
| 管理者/本人が再送したとき | 再送 | 有効なQRならあり |

- 5枚購入しても、受取人が未定のチケットは誰にも送らない。受取人が登録された時点で、その人のアドレスにだけ送る。
- 送信直前にサーバー側で、保有者・取消・入金・QRの失効を再確認する。失効済みのQRは送らない。
- 本文の個人情報は氏名とチケット番号だけ。電話番号・メールアドレスは載せない。
- 同じ保有者・同じQRに対する自動送信は1回だけ。再送は1チケット24時間に3回まで。
- 一時的な失敗（通信障害・429・5xx）は最大3回まで自動で再試行（定期ジョブが拾う）。宛先不正・ドメイン未認証などは再試行せず「失敗」と記録し、`/emails` から再試行できる。

## 注意

- 反映時点では**過去の参加者への一括送信はしない**（新しく発生するイベントだけ送る）。既存の参加者へ送り直す場合は、管理者の承認のうえ `/emails` から1件ずつ再送する。
- メールアドレスの所有確認（確認リンク）は未実装。誤入力された宛先へ送らないよう、`/emails` で宛先（一部伏せ字）を確認できる。
