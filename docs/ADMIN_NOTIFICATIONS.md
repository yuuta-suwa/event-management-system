# 管理者への登録通知と、入金後のチケットメール

## 1. 参加登録の管理者通知（「参加登録が1件ありました」）

参加者が申込を完了するたびに、管理者へ通知する。

- **宛先**: 有効な SUPER_ADMIN 全員と、そのイベントの担当者（イベントの `managerId`）。受付スタッフ・参加者には送らない。
- **文面**: 「参加登録が1件ありました（複数枚の申込は「（2枚）」を併記）」、イベント名、登録の累計／定員、入金済・未入金の件数、参加者名簿へのリンク。**氏名・電話・メールアドレスは載せない**（詳細はログインが必要な名簿で確認）。
- **方法**: メール（既定ON）と LINE（宛先を登録した人だけ）。各自が `/settings/notifications`（ヘッダーの歯車）で ON/OFF と LINE の宛先を設定する。
- **送信タイミング**: 申込の完了後、レスポンスを返したあとにバックグラウンドで送る。**通知に失敗しても、申込は成功する**。
- **二重送信防止**: 「登録 × 宛先 × 方法」ごとに1回だけ送る（`AdminNotificationLog.dedupeKey`）。結果（送信済／失敗／未設定のため送らない）は同じ画面の「最近の通知」に残る。
- **テスト**: 同画面の「テスト通知を自分に送る」で、自分宛てだけに実際と同じ形式で送れる。

### 使えるようにするための設定
| 方法 | 必要な設定 |
|---|---|
| メール | `docs/EMAIL_SETUP.md`（`RESEND_API_KEY` / `EMAIL_FROM`）。未設定の間は「送信しない」と記録され、設定すれば自動で送られる |
| LINE | 既存の `LINE_MESSAGING_ACCESS_TOKEN`。通知を受ける本人が公式アカウントを友だち追加 → `/settings/notifications` の宛先で自分の表示名（LINEユーザーID）を選んで保存 |

### 仕様上の注意
- 通知は**登録1件ごと**に送る（まとめ送り・日次サマリーは未実装）。まとめ送りにする場合は、定期ジョブ（`docs/SCHEDULER.md`）が必要。
- DB 変更: 新規テーブル `AdminNotificationPref` / `AdminNotificationLog` のみ（既存データに影響しない）。マイグレーション `20261117100000_admin_notifications`。

## 2. 入金確認後のチケットメール（実装済み）

入金確認（入金管理画面・集金担当の集金完了のどちらも）でチケットが有効になると、保有者のメールアドレスに「入金確認・QRチケット」を自動送信する（QR画像の添付・チケットURL・6桁の受付コード付き）。詳細と設定は `docs/EMAIL_SETUP.md`。

**メール送信サービス（Resend）が未設定の間は送られない。** 送信されなかった記録は `/emails` に「送信しない」と残るので、設定後は `/emails` から再送できる。
