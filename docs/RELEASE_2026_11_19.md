## 本番反映の手順（承認後）
1. Neon で念のためバックアップブランチを作る。
2. `DATABASE_URL`（本番）を指定して、マイグレーションを適用（**新しいテーブル `Checkout` を追加するだけ。既存データは変更しません**）:
   ```bash
   cd ~/Downloads/EVENT-MANAGEMENT-SYSTEM-handoff
   DATABASE_URL='（本番の接続文字列）' npx prisma migrate deploy
   ```
   - 適用されるのは `20261119100000_checkout_history`。
   - 同じチケットで「退出中」の行を1件までにする部分一意インデックスも含みます。
3. `main` にプッシュ（Vercel が自動デプロイ）。

## 注意・仕様
- 帳簿の閲覧範囲: 決裁権者に加えて、システム管理者（全イベント）と担当イベントの管理者（EVENT_MANAGER）。受付スタッフ・集金担当・参加者は不可。
- 帳簿に連動して、決裁権者が指定されたイベントの売上・経費画面も、同じ範囲の人に表示されます。
- 「発行して送る」は入金を記録します（立替=請求額、招待・無料=0円、入金確認済み=請求額）。監査ログ `TICKET_ISSUED_MANUALLY` に残ります。
- メール送信は Resend 未設定の間は「発行はしたがメールは未送信」と画面に表示します。
- 退出は受付済みの人だけ。同じ人の二重退出は「退出済み」と表示され、記録は増えません。
